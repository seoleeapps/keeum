# 코인 표기 통일과 Google Play 1.0.1 업데이트

2026-10-24 사용자 요청에 포함된 계획을 실행한다. 기준은 `v1.0.0`이며 제품명, 재화 수치와 계산, 젬, 저장 키, 공개 API와 데이터 형식은 유지한다.

| 화면 | 변경 후 표시 |
|---|---|
| 홈과 활동 잔액 | 동전 아이콘과 `250 코인` |
| 활동 비용 | `30 코인` |
| 활동 수입 | `코인 +50` |
| 정산 | `코인` |
| 잔액 부족 | `코인이 부족해요 — 활동 조합을 줄여 주세요` |

각 회차 `turn_index == 0`인 활동 화면에 “코인은 게임에서 얻고 활동에 사용하는 재화예요.”를 표시한다. 별도 저장 항목이나 팝업은 만들지 않는다. 기존 숫자 애니메이션의 `fmt` 인자로 단위를 유지한다. 기존 화면과 아트 방향을 재사용하는 문구 수정이며 새 화면이나 UI 개편은 아니다.

홈에서 활동을 열고, 활동을 선택하고, 정산을 확인한 뒤 홈으로 돌아오는 흐름은 유지한다. 화면 계층만 수정하며 엔진 독립 도메인과 어댑터는 바꾸지 않는다. 기존 예산 제한과 오류 처리도 유지한다. 설계 문서의 표시 기준과 Play 홈, 활동 스크린샷을 실제 렌더로 갱신한다.

## 인수조건과 검수

- AC-1: 사용자에게 보이는 원화 기호와 재화 이름 재력이 남지 않으며 비용, 수입, 정산, 잔액과 부족 안내가 위 표와 일치한다.
- AC-2: 첫 달 안내가 각 회차 첫 달에만 나타나며 다음 달과 재실행에서도 기존 턴 정보와 일치한다.
- AC-3: 잔액 0, 250, 9999999에서 기본 화면과 작은 화면, 큰 글자 설정을 검사한다. 잔액 애니메이션 중에도 코인 단위가 유지되고 글자나 버튼이 겹치거나 잘리지 않는다.
- AC-4: 실제 좌표 입력으로 활동 선택, 부족 조합 제한, 정산, 홈 복귀와 저장 복원을 확인한다. 재화 수치와 저장 키는 바뀌지 않는다.
- AC-5: 컴파일, `npm run test:core`, `npm run test:e2e`, 필수 CI와 중앙 출시 검증을 통과한다.

테스트 계획은 같은 폴더의 `test-plan.json`이다. 기존 입력 E2E에 표시와 첫 달 노출 assertion을 먼저 더해 요구사항 때문에 실패하는지 확인한다. 시각적 줄바꿈은 실제 렌더링 캡처와 사각형 검사를 병행한다. 실기기는 사용하지 않는다.

## 반영과 출시

브랜치와 Ready PR로 반영한다. 로컬 코드 리뷰와 CI 후 병합하고 병합 SHA에서 실행 근거를 다시 고정한다. 기존 절차로 `v1.0.1`과 원장의 Android 번호를 발급하고 내부 테스트에 올린 뒤 기존 공개 국가의 production 100%로 승격, 심사 제출, 승인과 실제 공개 상태를 확인한다. 국가, 가격, 정책 답변과 자격증명을 바꾸지 않는다. 문제 발견 시 공개 전 승격을 멈춘다. 원본 검수 자료는 NAS 복사와 직접 해시 대조 후 로컬에서 정리한다.

## 승인 근거

사용자는 이 계획 전문을 제공하고 “Implement the plan in a fresh context. Treat the plan as the source of user intent ... carry the work through implementation and verification.”라고 지시했다. 이는 위 변경, L1 개발 환경 검수, PR 병합, Google Play v1.0.1 기존 공개 국가 100% 업데이트와 공개 확인까지의 실행 승인이다. 기기 사용은 범위에 없다.

## 실행 중 추가 승인과 인증 복구

업로드에서 WIF 변수 두 개가 빠진 것이 확인된 뒤 사용자에게 기존 연결 복구를 요청했고, 사용자는 “기존 인증 연결 복구”를 선택했다. 새 키 생성과 기존 키 교체는 제외했다. 등록된 Publisher를 재사용하고, keeum 소비자를 등록했으며, 두 저장소 변수를 연결했다. 자격증명 백업과 로컬 및 BeeStation 사본의 복원 검사 후 수행했다.

기존 WIF 공급자의 seorilabs 허용 조건은 유지하고, GitHub 저장소 ID 1311181844와 소유자 ID 121283919의 main 및 v 태그만 허용 조건에 추가했다. 기존 Publisher에는 해당 저장소의 workloadIdentityUser 연결만 추가했다. 다른 정책 항목을 보존한 재조회와 실제 CI 인증 및 업로드가 통과했다. 게임 코드, 테스트 범위, 마켓, 버전과 국가 범위는 바꾸지 않았다.
