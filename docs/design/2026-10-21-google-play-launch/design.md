# Google Play 첫 출시 구현 설계

승인 근거: 2026-10-21 사용자가 전달한 「keeum Google Play 첫 출시」 계획의 구현 지시. 해당 계획의 제품 동작, 수치, L3 범위와 한국 전체 공개를 그대로 구현한다. 추가 마켓과 기기 접근은 이 승인에 포함되지 않는다.

## 범위와 화면 흐름

온보딩 → 홈 → 활동 두 칸과 선택적 광고 보너스 → 월 결과 → 이벤트 → 학기 정산 → 전환기 → 홈을 반복한다. 48턴 뒤 원서 → 엔딩 → 도감 → 다음 아이로 잇는다.

홈에는 선택형 `광고 보고 60젬`을 둔다. 상점은 기존 그림책 구성의 `꾸미기`로 바꾸고 뽑기와 옷장으로 연결한다. 전환기는 기존 확률의 가족 대화만 남긴다. 전면 광고는 학기 정산이 있었던 큐를 모두 끝내고 홈에 도착한 경우에만 후보가 된다. 가족 이벤트나 전환기, 입시와 엔딩을 거친 큐는 전면 광고 후보에서 제외한다.

## 책임과 데이터

- `core`: 기존 성장 공식과 활동 24종 유지. 이벤트 48개와 엔딩 40개를 JSON에서 읽는다. 명시한 우선순위와 조건 범위로 엔딩을 결정한다.
- `game/adapter/ad_gateway.gd`: 로컬 광고 설정, 카운트와 간격, 요청 식별자, 한 번만 지급하는 완료 처리를 소유한다. 화면은 SDK를 참조하지 않는다.
- Android 어댑터: Poing v5.1.0의 동의 갱신, 필요한 동의 창, 비동기 초기화와 광고 로드, 완료 및 닫힘을 연결한다. 실패하거나 준비되지 않으면 진행을 막지 않는다.
- 저장: 기존 파일과 백업 규약 유지. 광고의 일일 기준일은 앞으로만 이동한다. 새 필드는 구버전 저장에서 0이나 빈 값으로 복원한다.
- 테스트는 광고, 시계와 난수 경계만 대체한다. 저장은 프로세스별 격리 경로를 사용한다. 실제 시작 장면에 좌표 입력으로만 화면을 조작한다.

## 인수조건

AC-01 공개 CI는 ubuntu-latest에서 import, compile, 기존 코어 검사와 UI 스모크, 입력 E2E를 시간 제한 안에 실행한다. 원본 아트는 보존하고 모든 export에서 제외한다.
AC-02 활동 24, 이벤트 48, 엔딩 40, 전용 CG 12개이며 누락, 중복 ID와 다른 엔딩에 가려지는 조건을 검사한다.
AC-03 결제 상품, 구매 안내, 로그인, Firebase, 원격 설정, 지표 수집을 출시 경로에 추가하지 않는다. 뽑기 비용 150/1350, 확률 3/17/80%, 천장 40과 마일리지 수치는 유지한다.
AC-04 보상형은 세션 8회, 하루 18회, 60초 간격이다. 일일 젬은 60젬, 하루 1회다. SDK 완료 콜백 한 번만 보상하며 취소, 실패, 미준비와 중복 입력은 보상하지 않는다.
AC-05 전면 광고는 두 번째 세션부터, 180초 간격, 세션 2회와 하루 4회다. 보상형 종료 후에도 180초를 기다린다. 감정 화면에는 노출하지 않는다.
AC-06 시작부터 48턴, 입시, 엔딩, 도감, 다음 회차와 재실행 복원까지 좌표 입력으로 검증한다. 엔딩 조건 도달 검사와 실제 입력 완주는 증거를 구분한다.
AC-07 손상 저장, 구버전, 미완료 이벤트 복원, 날짜 역행, 광고 콜백과 무료 재화 뽑기를 검사한다. 변경 화면은 독립 실행 3회로 검수한다.
AC-08 API 36, 서명과 16KB 정렬, 실제 화면 등록 이미지, 계정과 패키지 소유권, 개인정보와 광고 선언, 연령등급을 확인한 뒤 내부 테스트와 한국 공개로 진행한다.

## 검증과 실패 처리

테스트 계획은 같은 폴더의 test-plan.json이다. 개발 환경은 headless 입력 E2E와 같은 여정의 렌더링 실행이다. 작은 비율, 긴 화면과 큰 글자를 확인한다. L3 통과 근거는 같은 후보 SHA의 CI이며 UI 독립 검수는 구현자와 다른 에이전트가 수행한다. 기기에서만 확인 가능한 실제 광고와 UMP 복귀는 개발 검수 후 최소 범위를 소명하고 별도 사용 승인을 기다린다. 미실행은 통과로 쓰지 않는다.

자격증명과 등록 ID가 없으면 임의 대체하지 않는다. 외부 상태를 변경하기 전 실제 계정과 대상 상태를 다시 읽는다. 리뷰, 서명, 업로드, 심사, 승인, 공개, 광고 게재는 각각 기록한다. 리텐션은 미측정이다.

## 적용과 복구

격리 worktree의 브랜치와 Ready PR로 반영한다. main과 PR에서는 검사만, 명시한 출시 태그에서만 AAB를 만든다. 실패 후보는 승격하지 않고 기존 저장과 아트 원본을 보존한다. 새 데이터는 기존 엔딩 ID와 성장 공식을 유지한다.
