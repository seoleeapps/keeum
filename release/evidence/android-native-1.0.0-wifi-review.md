## 확인과 차단

기존 Wi-Fi는 활성, 연결, 기본 네트워크, VALIDATED 상태였다. 모바일 데이터 활성 플래그는 읽기만 했다. Wi-Fi 재연결이나 다른 설정 변경은0건이며 복원할 변경도 없다. SSID와 주소는 기록하지 않았다.

일반형 테스트 참여 URL은 실제 Console 내부 테스트 링크와 달랐다. root가 Console에서 읽은 실제 링크로 이동한 뒤 해당 앱 초대를 실제 터치로 수락했고 “테스터” 상태를 확인했다. 계정과 테스터 목록은 바꾸지 않았다.

실제 참여 페이지의 “Download test app”을 눌러도 native Play는 “항목을 찾을 수 없습니다.”를 표시했다. 참여 후 새 조건에서 현재 설치된 앱을 한 번 시작했지만 `Local install check failed due to wrong installer.` 뒤 프로세스가 종료됐다. 기존 Play 생성 APK의 adb 설치 출처를 그대로 기록했으며 Play Store 설치라고 주장하지 않는다. 이번 구간의 데이터 삭제, APK 교체 설치, 설치 출처 위장과 보호 해제는 없다.

현재 native Play의 선택 계정은 필요한 라벨이 노출되지 않아 확인하지 못했다. 현재 계정 컨트롤만 읽었고 계정 선택, 전환, 추가, 로그인이나 다른 앱 목록 수집은 하지 않았다. 계정 문제로 원인을 단정하지 않는다.

실제 UMP 응답과 필요한 동의 창, GMA 초기화, 광고 요청과 로드, Test Ad, 보상형 취소와 완료 지급60 한 번, 실제60초 간격, 전면 광고와180초 제한, 광고 종료 후 게임 복귀는 확인하지 못했다. Poing 플러그인 등록 완료 로그를 이 항목들의 통과로 확장하지 않았다. 실제 SDK 요청이 이뤄졌는지도 이 로그만으로 단정하지 않는다.

자체 앱은 실행 중 스스로 종료했고 UID 로그 스트림도 정리했다. 공개 후5분은 시작하지 않았다. 새 기기 승인 전 adb를 다시 실행하지 않는다. 원시 식별자, 현재 계정 값과 외부 앱 화면은 이 공개용 요약에 포함하지 않았다.
